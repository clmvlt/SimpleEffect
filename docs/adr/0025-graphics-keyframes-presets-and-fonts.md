# 0025 — Graphics, animatable styles, data-defined animation presets and the font catalogue

- Status: Accepted
- Date: 2026-11-07

## Context
Prompt 15 makes texts, shapes and images complete motion-design building blocks: full text styles (font, weight, outline, shadow, plate, spacing, wrapping, case, a typewriter reveal), outlined shapes and lines, image fits, keyframes on every animatable property with easing curves, a library of animation presets (fade, slides, pop, blur, typewriter, bounce, shake, pulse), direct manipulation in the viewer and keyframe editing in the timeline. AI agents (prompt 19) must reach the same features through the same code. Open questions: which style values animate and how the domain reaches them without one code path per property; where preset expansion lives so the UI and agents agree; how texts get exactly the same fonts in preview and export; how the viewer knows where a text is (its box depends on font metrics); and how continuous gestures stay one undo step.

## Decision
- **One table of animatable properties.** `AnimatableProperty` (17 values: position, scale, rotation, anchor, opacity, blur, volumeDb, fontSize, fillColor, letterSpacing, reveal, strokeColor, strokeWidth, shadowColor, shadowBlur, shadowOffset, backgroundColor) and `ItemKind::property` / `property_mut` return a typed slot (`PropertyRef`/`PropertyMut`: number, design pixels, pair or colour) for any item kind. `SetKeyframes`, preset expansion and validation (keyframe rules, `AnimatableProperty::allowed_range`) all go through it; `PropertyAnimation` (one variant per property, generated by a macro) is the typed value. The renderer mirrors the table (`shared/animation/property-access.ts`, checked against the protocol type at compile time).
- **Style model.** `TextStyle` gains weight, italic, an animatable size and colour, `Stroke` (shared with shapes: enabled, colour, visible width outside), `TextShadow`, `TextBackground` (the item's box includes the plate), letter spacing, line height, alignment, wrapping width, case; `TextItem.reveal` (0–1 of the characters, in reading order). Shapes gain `Line { length, thickness }` (a capsule), an outline and `coverFrame` (the box is the sequence frame whatever its format, the fit mode ADR-0015 announced); images `fit: fit | fill | natural` (one image pixel per design pixel); every transform a `blur` in design pixels. Disabled outlines, shadows and plates keep their values. Schema version 5 (migration wraps the old bare size/colour/fill values); `Animatable` also reads a bare value, so older journals replay.
- **Presets are data, expanded in Rust.** `crates/se-domain/assets/animation-presets.json` (embedded, checked at load: unique ids, phases `[in, out]` or `[emphasis]`, sorted positions, value forms fitting the property). A preset lists per property keyframes at positions 0–1 of its span with values relative to the item's own value (`base`, `absolute`, `offset`, `factor`). `ApplyAnimationPreset { item, preset, phase, duration, start }` expands into ordinary keyframes (`expand_preset`): the span sits at the start (in), the end (out) or the middle (emphasis) unless a start is given, clamped into the item; the base is the property's value at the far end of an entrance (start of an exit or emphasis) read as a **hold** of existing keyframes (the domain never interpolates); keyframes inside the span are replaced, others kept; the exit plays the entrance backwards (positions `1 − at`, easings mirrored). The UI never expands presets: `listAnimationPresets` gives each preset's expansion on a reference text (`samples`) for hover previews.
- **Fonts are a core catalogue served over `/media`.** The new `se-fonts` adapter implements the `FontCatalog` port: bundled families (latin and latin-ext WOFF2 subsets of Inter, Montserrat, Oswald, Playfair Display, Bebas Neue, Permanent Marker — OFL or Apache 2.0 — embedded in the binary, so no packaging step) then installed families (`fontdb`, read once in the background at startup). `listFonts` lists them; `GET /media/fonts/{id}` serves a face. The engine's `FontRegistry` (`@se/engine/fonts`) registers the catalogue's faces as `FontFace`s and loads a family's faces the first time a frame's text uses it; `FrameRenderer` waits for them (4 s at most) before drawing, so preview and export draw identical glyphs. A family absent from the catalogue is drawn with Inter and reported (`missingFonts` in the preview state, a viewer badge, an inspector warning).
- **Text layout happens once, in the compositor.** The Pixi text node measures the whole text without outline or shadow (wrapping, line widths) and draws it line by line at aligned positions, so revealing characters, outlining or shadowing never moves the text; outlines are drawn twice the width centred on the glyph outline (the requested width shows outside). `Compositor.render` returns every layer's box; the preview engine publishes a `FrameLayout` (transform + box per layer) after each drawn frame — the viewer's handles and hit tests read it.
- **Continuous edits preview locally, then commit once.** The renderer's `propertyPreviewStore` holds the values of a gesture in progress (gizmo drag, inspector scrub, text typed in the viewer); the viewer draws items with them; on release one command is sent (`setItemAnimations`: several properties of several items in one transaction, keyframed properties getting a keyframe at the playhead) and the preview clears when it resolves or fails. Keyframe lanes in the timeline follow the same rule (drag preview in their store, one command on release).
- **Graphics are placed by the core.** `addGraphicItem { sequenceId, at, duration, graphic: text | shape | image }` puts the new item (default look from `TextItem::new`, `ShapeItem::new`, `ImageItem::new`) on the highest unlocked, visible video track free over its span with nothing above it at that time, or on a new video track on top — one undo step.

## Consequences
- An AI agent applying `fade` or editing `strokeWidth` produces exactly what the UI does, and the result stays ordinary editable keyframes (golden rule 6).
- Adding an animatable property is a variant, a slot, a range and a `PropertyAnimation` line in Rust plus the renderer mirror and an inspector row; nothing else changes.
- The binary grows by about 0.8 MB of fonts; projects using installed fonts may look different on another machine (the catalogue says which families are bundled).
- Text goldens use the bundled Inter and compare 4 × 4 block averages: platform rasterisers differ at glyph edges even for the same file.
- The preview state and the compositor interface changed shape (`missingFonts`, returned boxes): export (prompt 27) reuses them as they are.

## Alternatives considered
- **Expanding presets in TypeScript**: two implementations to keep equal, and agents would bypass the UI's. Rejected (the prompt asked for Rust).
- **Interpolating in Rust to find a preset's base value**: duplicates the engine's easing code; a hold of existing keyframes is exact for static properties and predictable otherwise.
- **System fonts by name only (canvas font matching)**: no load signal, so export could draw before a font is ready, and bundled fonts would need a renderer-only list unknown to agents.
- **Measuring texts in pure code**: needs font metrics outside a canvas; the compositor measures while drawing and reports boxes instead.
