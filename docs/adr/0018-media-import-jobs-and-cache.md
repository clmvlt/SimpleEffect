# 0018 — Media import, background jobs and the derived-file cache

- Status: Accepted
- Date: 2026-11-07

## Context
ADR-0007 chose sidecar ffmpeg/ffprobe processes, mezzanines and a job queue; prompt 08 implements the first half: importing files, probing them, generating thumbnails and waveform peaks in the background, serving them to the renderer, and noticing originals that moved. Several questions were open: how to recognise a file already imported (or moved), where derived files live and whether the document records them, how the renderer's decodability check is stored, how a job is cancelled without leaking ffmpeg processes, what format peaks use on the wire, and which ffmpeg builds are fetched.

## Decision
- **Content fingerprint** (`se_domain::ContentFingerprint`, computed by se-media): size, modification time and xxh3-64 of the first and last mebibyte (2 MiB read at most). Same size and sample hash = same content: an import of content the project already has (or of the same file twice in one request) is reported as a duplicate, and a relink to other content asks for confirmation (`RelinkOutcome::ContentDiffers`, then `force`). The cache key `<hash>-<size>-<mtime>` also includes the modification time, so a file rewritten in place gets fresh derived files. The sample hash is validated (16 lowercase hex digits): it names a folder.
- **Derived files are cache, not document.** Thumbnails and peaks go to `<project>/cache/media/<cache key>/` (`thumbnails.jpg`, `poster.jpg`, `thumbnails.json`, `peaks-256|1024|4096.sepk`), written under temporary names then renamed (the JSON last), so a file that exists is complete. The document does not record them: the cache is the truth, jobs are queued again for any missing output when a project opens or an asset is imported or relinked, and undo/redo never loses them (they are keyed by content). Mezzanines and proxies (prompt 09) stay in `DerivedMedia` as ADR-0007 says. The cache folder layout is known by se-app (`media_paths::media_cache_dir`) and the file names by se-media (`cache_layout`).
- **Document schema version 2.** Assets gain `fingerprint` (nullable) and a per-stream `decodability: { video, audio }` (`unknown | decodable | undecodable | noStream`), so prompt 09 can decide mezzanines from the picture and the sound separately; `MediaInfo` gains codec `level`, `codecTag`, `pixelFormat` and the audio `profile` (needed for WebCodecs codec strings). `migrate_v1_to_v2` converts older documents.
- **`Actor::System`** marks facts the app records itself — missing flags at opening, decodability reports — journaled like any commit but never in the undo history or a changeset. Import, relink and remove are user transactions (undoable, labels `Import media`, `Relink media`, `Remove media`).
- **Missing originals** are checked by the media service when a project opens (`ProjectObserver::project_opened`, before the session is returned): an original found at its path clears `missing`; one found through its relative hint with the same content is relinked silently; otherwise `missing` is set.
- **`JobQueue` (se-app) is generic**: a job is a `JobWork` future with a kind (concurrency limit per kind: 2 thumbnails, 2 peaks), a priority (thumbnails high, peaks normal; equal priorities run oldest first), a project and an asset. One automatic retry. Cancelling aborts the job's task, which drops the work's future; the closing of a project cancels and forgets its jobs and waits (≤ 5 s) for their tasks to stop. Events: `jobQueued`, `jobProgress` (at most one per percent), `jobCompleted`, `jobFailed`, `jobCancelled`; job events carry the snapshot in a `job` field (flattened, the job's `kind` would clash with the event tag).
- **One spawn helper** (`se_media::process::Sidecar`, over `process-wrap`): job object + `CREATE_NO_WINDOW` on Windows, new process group on Unix; dropping a `Sidecar` that has not exited kills the whole tree. This is what makes cancellation by dropping safe.
- **Tools** are looked up on every use: the folder set by the user (library setting `media.toolsDir`), the folder of se-core (packaged: `resources/bin/`), `resources/bin/<platform>/` in an ancestor of it (development), then the `PATH`; `MEDIA_TOOLS_MISSING` otherwise.
- **Thumbnails**: up to 40 tiles of 90 px high (one per second for short clips), 8 per row in one JPEG, sampled with `select` on keyframes only for media longer than 30 s (fast on long files; tiles then follow the keyframe interval), their real times printed by the `metadata` filter into the JSON layout (`ThumbnailSheet`); a poster up to 360 px high at 10 % of the duration. Images get one tile and a poster.
- **Peaks**: ffmpeg decodes the first sound stream (at most 2 channels, native rate) to `f32` PCM on stdout; min/max per channel per 256 samples, then 1024 and 4096 by merging; one `SEPK` file per level (32-byte little-endian header, then `Int16` min/max pairs), read in the renderer as an `Int16Array` without copying. Progress comes from the samples read (stdout carries the PCM).
- **`/media` routes** (se-core, behind the access guard, token as `?t=`) serve originals and derived files with tower-http's file service: Range (206/416), `HEAD`, `If-Modified-Since`, explicit content types, `Cache-Control: no-cache`. Asset ids are globally unique, so routes need no project id.
- **Decodability is checked by the renderer** (`@se/engine/capabilities`: codec strings from `MediaInfo`, `VideoDecoder`/`AudioDecoder.isConfigSupported`, `ImageDecoder.isTypeSupported`) for every asset with an `unknown` stream, and reported with `reportDecodability`.
- **Binaries**: `pnpm fetch-binaries` downloads FFmpeg 9.0.2 builds pinned by URL, size and SHA-256 (from GitHub asset digests or the builder's `.sha256`): Gyan.dev essentials (Windows), Martin Riedl (macOS arm64/x64, signed, not notarized), BtbN GPL 9.0 branch build (Linux; monthly builds are kept two years). All are GPL v3 builds, acceptable for personal use; the script asks before downloading (`--yes` in CI) and the release workflow bundles them as `extraResources`.

## Consequences
- Re-importing or relinking is cheap and safe; renaming a file in place keeps its identity, editing it in place regenerates its previews.
- Deleting `cache/` costs only regeneration time. Two assets with the same content share a cache folder (and are deduplicated anyway).
- A media job never blocks the UI or the core: processes run outside, and their outputs appear atomically.
- The renderer must check decodability itself; a core alone cannot know what the user's GPU decodes.
- Installers published with these binaries carry GPL obligations (source offer); the Linux build must be bumped before October 2028, when BtbN prunes it (backlog). macOS notarization of the bundled tools is open (backlog).

## Alternatives considered
- **Full-file hashes**: exact but reads gigabytes per camera file at import. Rejected for the sampled hash.
- **Recording thumbnails/peaks in `DerivedMedia`**: every job completion would be a document commit interleaved with the user's undo history, and an undo of an import followed by a redo would lose them. Rejected.
- **Killing only the direct child process** (`kill_on_drop`): enough for ffmpeg today, but not for tools that spawn helpers; the Windows job object costs nothing more. Rejected.
- **JSON peaks or 32-bit float peaks**: twice to ten times larger for one hour of sound; 16-bit is plenty to draw. Rejected.
- **One ffmpeg seek per tile** (`-ss` before each input): exact times but N demuxer openings, and slow on long-GOP footage without keyframe-only decoding. Rejected for the single keyframe pass.
- **eugeneware/ffmpeg-static or shaka-project builds** (one source for every platform): mixed FFmpeg versions per platform, or a minimal codec set (no dav1d, no zlib on Linux). Rejected; osxexperts and evermeet (macOS) rebuild files in place or publish no hash. Rejected.
