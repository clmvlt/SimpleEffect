# 0019 — Mezzanines, proxies, media analyses and media settings

- Status: Accepted
- Date: 2026-11-07

## Context
ADR-0007 chose mezzanines and proxies for footage WebCodecs cannot play, and analyses for the AI; ADR-0018 built the import, the job queue and the content-keyed cache. Prompt 09 implements the rest of the pipeline: deciding when an asset needs a mezzanine or a proxy and how to make it, encoding with the GPU when possible, analysing sound (silences, loudness) and pictures (shot changes), extracting frames for AI tools, ordering all these jobs, and the settings screen. Open questions: where the decision lives and what it depends on, how derived states reach the document without racing each other, where analysis results go, how jobs of different kinds are prioritised when each kind has its own slots, and what the user can configure.

## Decision
- **A pure policy in se-app** (`media_policy`): `mezzanine_decision(asset, capabilities, quality)` → `Waiting` (a stream's decodability is still unknown) | `NotNeeded` | `Needed(TranscodeRecipe)`, and `auto_proxy_wanted` / `proxy_recipe`. A mezzanine is needed when the renderer reported the picture or the first sound stream `undecodable`, or when the picture's layout is outside 4:2:0 at 8–10 bits (4:2:2, 4:4:4, 12 bits may pass `isConfigSupported` yet decode badly). The picture becomes **HEVC Main 10 when the source has more than 8 bits and this machine decodes HEVC Main 10, H.264 High 4:2:0 8 bits otherwise** (the user chose H.264 for 8-bit sources: faster to encode, decoded everywhere, nothing lost); quality = the CRF of the settings (default 14), same size and rate, a keyframe about every second. A decodable picture is copied when only the sound needs work. Sound is copied when decodable and MP4-compatible, else AAC 320 kb/s (FLAC when the machine has no AAC decoder). Sound files get an M4A mezzanine, undecodable stills a PNG. Proxies: H.264 High 8 bits, shorter side 540 or 720 (never enlarged), CRF 23, `-tune fastdecode`, no B-frames, a keyframe every 15 frames; automatic (setting) for videos whose shorter side exceeds 1080 or whose picture needs a mezzanine, and on request (« Générer un proxy »).
- **Decoder capabilities are reported by the renderer** (`reportDecoderCapabilities { hevcMain10, h264High, aac, flac }`, 4K configurations) once per session before decodability reports, and kept in `library.db` so decisions made before the report use the last one (default: H.264 + AAC + FLAC, no HEVC).
- **Derived states in the document, files in the cache.** `DerivedMedia { mezzanine, proxy: Option<DerivedFile { relativePath, status: pending | ready | failed { message } }> }`, files at `cache/media/<cache key>/mezzanine.<mp4|m4a|png>` and `proxy-<540|720>.mp4`. Every state change is a **system transaction** (`Queue derived media` when queued, `Record derived media` when a job ends): never undone, so an undo never resurrects a deleted file. `AssetPatch` has one field per derived copy and per analysis summary (`mezzanine`, `proxy`, `audioAnalysis`, `sceneDetection`, each `Assign<Option<…>>`) so jobs finishing together never overwrite each other. A job records `ready` only if the asset still waits for that very file (`pending`, same path): a relink to other content clears derived copies and summaries, and late jobs of the old content change nothing. On the last attempt, a failing job records `failed` with ffmpeg's message. When a project opens (and after a cache cleanup), pending copies are queued again, ready copies whose file disappeared are regenerated, failed ones are tried again.
- **Analyses** (`se_domain::analysis`): `AudioAnalysis` (integrated loudness, loudness range, true and sample peaks, the 3 s short-term loudness every 0.5 s, silences: RMS of 20 ms windows under −40 dBFS for at least 0.5 s) measured in one pass on ffmpeg's PCM by se-media on the blocking pool (crate `ebur128`); `SceneDetection` (ffmpeg `select='gt(scene,0.3)',showinfo` on a 320 px copy, split so `-progress` sees every frame). Full results go to `project.db` (`analyses`: one row per asset and kind with the **content key** analysed and a payload format version, schema v2) through the `AnalysisStore` port that the project store hands to the actor handle (not document state, so not written through the actor). The asset keeps a **summary** (`Asset.analysis: AssetAnalysis { audio: AudioSummary?, scenes: SceneSummary? }`, document schema v3). An analysis runs once per content: a stored result with the asset's current key is reused (and summarised again if the summary never landed).
- **Priorities across kinds**: the queue keeps per-kind slots (thumbnails 2, peaks 2, mezzanine 1, proxy 1, audio analysis 2, scene detection 1) and adds a **global limit of 4 running jobs**, so priorities order kinds: thumbnails and peaks (`High`) > proxies and mezzanines of media a clip uses (`Normal`) > analyses (`Low`) > mezzanines of unused media (`Idle`). Running jobs are never pre-empted.
- **Hardware encoding** (se-media `encoders`): candidates per OS in `platform.rs` (NVENC on Windows; VideoToolbox on macOS; NVENC then VAAPI on Linux), each tried once per ffmpeg path with a 5-frame test encode using the very arguments jobs use (listing encoders is not enough: builds list NVENC without an NVIDIA GPU); the result is cached and detected in the background at startup. The CRF maps to `-cq` (NVENC), `-q:v` (VideoToolbox, `100 − 2.5 × CRF`) and `-qp` (VAAPI). A failing hardware run is retried in software (libx264/libx265) within the same job.
- **Geometry**: derived copies keep the coded picture and its display rotation (`-noautorotate` copies the display matrix), so the engine treats originals and copies alike with the asset's `MediaInfo`. Outputs are written as `<stem>.part.<ext>` and renamed.
- **Frame extraction is a service, not a job**: `MediaService::extract_frame(project, asset, time, max_width)` → a cached JPEG at `cache/media/<key>/frames/<flicks>-<width>.jpg` (upright, never enlarged, the last frame when the time is the very end), for MCP tools (prompt 18). Times outside the media are `MEDIA_TIME_OUT_OF_RANGE`.
- **Settings** (`library.db` keys `media.*`): mezzanine quality (CRF 8–28), proxy resolution (540p/720p), automatic proxies, ffmpeg folder (`MediaTools::set_tools_dir` updates the shared `ToolLocator` at once). The screen shows the project cache's location and size and cleans it (`clearProjectCache`: jobs stopped, `cache/` deleted past files in use, everything needed queued again; analyses kept). The user chose a modal « Réglages » dialog and a read-only cache location.
- **Playback source** (`@se/engine/sources`): a ready mezzanine is used whenever it exists; otherwise the original plays once no stream was refused and no mezzanine is pending; an undecodable asset without a ready mezzanine is « en préparation » (or « illisible » if it failed). The media bin shows it as a badge.

## Consequences
- Pro footage becomes playable without user action; the mezzanine of an unused clip never delays previews or analyses.
- The document records derived states (the renderer and agents see them through normal patches) but stays free of progress noise (job events carry progress).
- AI tools (prompt 18) read silences, loudness curves and shot changes from `project.db` and see summaries with each asset; silence cutting (prompt 22) can reuse the stored ranges or recompute from the cached peaks with other thresholds.
- Mezzanines decided on a machine with HEVC decoding may not play on another machine (backlog); the cache location is per project only (backlog).
- Software HEVC encoding is slow; machines without a GPU encoder get H.264 for 8-bit footage and pay for x265 only on 10-bit footage.

## Alternatives considered
- **The policy in se-domain**: it depends on settings and machine capabilities, not on the document alone. Rejected for se-app.
- **One `derived` patch field replacing both copies**: a mezzanine and a proxy finishing together would overwrite each other's state. Rejected for one field per copy.
- **User transactions for derived states**: undo would bring back « ready » states whose files were cleaned. Rejected.
- **Analyses in the document**: one short-term loudness value per half second is too large for every snapshot and patch. Rejected for `project.db` + summary.
- **Analyses as cache files**: they are facts the AI relies on and cost a full decode; they belong to the project (copied by « Dupliquer »). Rejected.
- **Per-kind slots only**: every kind runs at once (up to 8 ffmpeg processes) and priorities only order jobs of one kind. Rejected for the global limit.
- **Trusting `ffmpeg -encoders`**: lists encoders whose hardware is absent. Rejected for test encodes.
- **Auto-rotating derived copies**: their size would differ from the original's `MediaInfo` and the engine would need to know which file is rotated. Rejected.
- **A configurable global cache folder** (`cache/` outside the project): the user kept the project folder (backlog).
