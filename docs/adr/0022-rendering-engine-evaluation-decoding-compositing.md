# 0022 — Rendering engine: evaluation, frame-accurate decoding, compositing and golden frames

- Status: Accepted
- Date: 2026-11-07

## Context
Prompt 12 builds the first half of `@se/engine` (ADR-0002): show in the viewer the exact frame of the sequence at the playhead, with the code export will reuse. Open questions: how a source frame is chosen so that scrubbing is exact at 29.97 fps and across containers that round timestamps; who owns `VideoFrame`s (they hold GPU memory and stall hardware decoders when kept); how a proxy can replace the original without changing the framing; what an image's « natural size » is (the domain gives clips a `reframe` mode but not images); how the engine stays outside React while the viewer drives it; and how golden-frame tests can give the same pixels on macOS, Windows and Linux.

## Decision
- **Pure evaluation in domain units.** `evaluate(sequence, assets, time) → FrameGraph` lists, bottom first, one layer per visible video track (the item covering `time`, half-open ranges, binary search): `video`, `image`, `shape`, `text`. Transforms are resolved keyframes in ADR-0015 units; box sizes are sequence pixels (design pixels × design scale). Fades multiply a clip's opacity (linear, from black at the start, to black at the end). Captions draw as basic text with a fixed look until caption styles (prompt 23); motion templates draw nothing until prompt 24. Layers that draw nothing (opacity 0, zero scale) are dropped so their media is never decoded.
- **Natural box from the asset, never from the decoded file.** A video's box is its upright display size (coded size with the display rotation applied; pixels taken as square) fitted or filled into the frame by `reframe`; the decoded pixels — original, mezzanine or proxy — are stretched over that box. Switching variants therefore never moves or resizes anything. **Images fit the frame at scale 1** (like a `fit` clip): resolution-independent, and agents reason with relative scales only.
- **Interpolation.** Linear, hold (the value holds until the next keyframe's exact time), CSS cubic Bézier (Newton–Raphson with a bisection fallback), presets = CSS `ease-in`/`ease-out`/`ease-in-out` (the curves `@se/ui`'s easing editor offers). Colours blend in OKLab with premultiplied alpha (CSS Color 4). `docs/test-vectors/interpolation.json` holds the expected values, computed by an independent bisection reference, for a future Rust evaluator.
- **Media time and frame lookup.** Media time 0 is the first frame (its timestamp, or 0 when an edit list hides earlier frames), as ffmpeg treats it, so an original and its transcoded copies share times. With the asset's frame rate, the source frame index is computed exactly in flicks (`⌊source time / frame duration⌋`) and the decoder is asked for the frame at the **middle** of that frame (`frameLookupTime`): exact at frame boundaries (one flick before a boundary still shows the earlier frame) and robust to containers storing milliseconds (Matroska/WebM put 29.97 fps frames up to 0.5 ms off). Without a known rate (variable frame rate), the lookup is one microsecond past the time.
- **The decoder pool owns every picture.** One Mediabunny source per (asset, variant) over se-core's `/media` URLs; an LRU cache of pictures keyed by source **and URL** (new content never reuses old pictures) with a byte budget (256 MiB) and a count limit (48) because hardware decoders stall when too many frames are held. Callers **lease** pictures; the compositor uploads them during a synchronous `render` and keeps no reference, so leases are released right after drawing and the cache closes a picture only once evicted and unleased. Decodes of one source run one at a time; requests aborted before they start are skipped (a newer frame request aborts the previous one). A `FrameTracker` counts open `VideoFrame`s and `ImageBitmap`s (exposed in development as `window.simpleEffectPreviewStats()`; tests require zero after destroy).
- **Compositor behind an interface.** `Compositor { resize, setBackground, render, destroy }`; `PixiCompositor` draws on WebGL 2 (WebGPU optional) on an `HTMLCanvasElement` or an `OffscreenCanvas`, in sequence pixels scaled to the canvas, reusing one node per item. `pixi.js/unsafe-eval` is loaded so PixiJS runs under the renderer's CSP (no `unsafe-eval`).
- **Drawing policy.** A frame whose pictures are all cached is drawn synchronously; otherwise the engine reports `loading`, keeps the previous image and draws once every picture is decoded, unless superseded. Media that cannot be drawn becomes a per-asset issue (`preparing`, `missing`, `mezzanineFailed`, `decodeFailed`) shown by the viewer; the frame is drawn without it.
- **Engine outside React.** The renderer imports `@se/engine/preview` lazily (only when a viewer shows a sequence and WebCodecs exists). `ViewerEngineController` owns the engine: it mounts a **fresh canvas** for each engine (a lost WebGL context cannot be recovered, and React StrictMode mounts twice), buffers settings while the engine starts, and is fed by a thin hook; the playhead store drives it directly, without React renders. The preview canvas draws at most the sequence resolution (more pixels would only upscale video); fixed zooms show one sequence pixel per CSS pixel at 100 %.
- **Golden frames.** Vitest browser mode in headless Chromium (Playwright) with WebGL forced onto SwiftShader and decoders asked for software decoding, so references match across GPUs and OSes. Fixtures (videos encoding their frame number in binary, a proxy, a rotated copy, VP9, colour bars, an alpha disc) are generated once by `scripts/generate-golden-fixtures.mjs` and **committed** (≈35 kB): tests never need ffmpeg. References are PNGs compared with a tolerance (16 levels per channel, 0.5 % of pixels); text is checked by placement only (fonts differ per OS).

## Consequences
- Scrubbing is frame-exact, including 29.97 fps and other sequence rates over the clip's rate; the proxy toggle changes only sharpness.
- Export (prompt 27) reuses `evaluate`, `FrameRenderer` and `PixiCompositor` on an `OffscreenCanvas`; playback (prompt 13) adds sequential decoding (one decoder per run instead of one per `getSample`) and the audio clock on top of the same pool.
- Images placed by users or agents start fitted to the frame; a logo needs a scale below 1.
- `pnpm check` needs Playwright's Chromium (`pnpm exec playwright install chromium`, once per machine; CI installs and caches it).
- Decoding and demuxing still run on the renderer's main thread (WebCodecs decodes off-thread); moving the engine into a Worker stays possible since it only needs a canvas abstraction.

## Alternatives considered
- **Seek with a small epsilon past the sequence time**: one microsecond works for MP4 but shows the wrong frame for millisecond-rounded containers; a half-millisecond epsilon fixes those but switches frames early at boundaries. The exact frame index with a mid-frame lookup has neither problem.
- **Cache `ImageBitmap` copies instead of `VideoFrame`s**: frees decoder buffers at once, but costs a GPU copy per frame; the count limit keeps hardware decoders flowing.
- **Boxes from the decoded frame size**: a half-resolution proxy would shrink the picture or need per-variant scaling everywhere.
- **Images at native pixel size** (pixels as design pixels): natural for small logos, but a 4000 px photo would overflow the frame and every placement would depend on the file's resolution.
- **GPU rendering in golden tests**: faster, but pixels differ between GPUs and drivers; SwiftShader trades speed for identical references.
- **Fixtures generated at test time by ffmpeg**: no binary files in Git, but tests would skip without ffmpeg and change with ffmpeg versions.
