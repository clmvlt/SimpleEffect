# se-mcp

## Purpose
The MCP server exposing SimpleEffect tools to AI agents: the agents' only way to read and change a project (ADR-0003, ADR-0028, ADR-0029). se-core mounts its streamable HTTP service at `/mcp`; every call comes from one running task (its bearer token resolves to an `AgentContext`). Tools translate MCP calls into `se-app` use cases; they never mutate documents themselves: write tools hand typed `AgentEdit`s to `se_app::AgentEditService`, which plans them, checks the task's scope and commits one AI transaction recorded in the task's changeset. Prompt 18: the server and the read tools; prompt 19: write tools, `apply_batch`, `get_task_changes`; ADR-0034: `transcribe_media`.

The contract with agents — conventions, every tool's input, output and errors — is `docs/ai-tools.md`. Keep it, the tools and the schema snapshots in step.

## Public API
| Item | Role |
|---|---|
| `mcp_service(McpDeps)` | The `rmcp` `StreamableHttpService` se-core nests at `/mcp` (sessions in memory, closed after 5 min idle) |
| `McpServer::new(McpDeps)` | The `ServerHandler`: `get_info` (name `simpleeffect`, short instructions), `list_tools`, `call_tool` (resolves the bearer token of the request's `http::request::Parts` → `ACCESS_REVOKED` when the run is over); `call(agent, name, arguments)` runs a tool without HTTP (tests); `tools()` |
| `McpDeps { projects, media, renders, tokens, edits, transcription, smart_cuts, captions, template_checks, library_templates, reframing }` | The se-app services tools read through (`transcription`: `TranscriptionService::sequence_words` and `search`, prompt 21; `smart_cuts`: `SmartCutService::settings` and `media`, prompt 22), and `edits` (`AgentEditService`), the only way they write |
| `cuts::{run_cut, seconds_in}` | Smart-cut tools (prompt 22): a `CutRequest` run through `AgentEditService::apply_cuts` (cut scope rule) and the summary agents get (`cuts`, `removed`, `words_removed`, first 50 `ranges` in sequence time before the cut, `tracks`, `revision`, `note`, `untranscribed`, `unanalysed`) |
| `template_io::{find_template, template_summary, TemplateSummary, param_values, push_frames}` | Motion template tools (prompt 24): lookup (`TEMPLATE_NOT_FOUND` listing the project's templates), the compact description agents read (parameters with types, defaults, ranges, options; instance count), parameter values read from JSON against the template's schema (keyframes for numbers and colours; `INVALID_ARGUMENTS` naming the parameter), the check's pictures as images with caption lines |
| `library_io::{library_template, as_template, library_summary, LibrarySummary}` | Library tools (prompt 25): an entry read through `TemplateLibraryService` as a motion template (malformed id `INVALID_ARGUMENTS`, missing `LIBRARY_TEMPLATE_NOT_FOUND`, caption style refused), the summary agents read (category, tags, version, parameters with brand roles, the project's copy) |
| `bearer_token(&HeaderMap)` | `Authorization: Bearer <token>` (also used by se-core's `/mcp` guard) |
| `tools::catalogue()` | Every `ToolEntry`, in the order agents see them |
| `registry::{McpTool, ToolEntry}` | The tool contract (`READ_ONLY`, `DESTRUCTIVE` defaulting to `!READ_ONLY`) and its type-erased form |
| `output::{ToolOutput, ToolError, codes}` | Compact JSON + JPEG results; errors with stable codes (`INVALID_ARGUMENTS`, `INVALID_TIME`, `*_NOT_FOUND`, `NOT_ANALYSED`, `TOO_MANY_FRAMES`, `ACCESS_REVOKED`, `INTERNAL`; use-case errors keep their protocol code) |
| `time_io::{TimeInput, RangeInput, TimeOutput, RangeOutput}` | Times at the boundary: seconds or timecode in, `{timecode, seconds}` out |
| `context::{ToolContext, find_sequence, find_tracks, find_item, find_asset, default_range, whole_sequence}` | The call's services and caller; lookups with actionable errors listing what exists |
| `describe::{item_summary, asset_summary, track_summary, …}` | Compact descriptions shared by tools |
| `timing::{ClipWindow, merge, complement, spread}` | Range sets and frames spread over a range; `ClipWindow` (source ↔ sequence time of clips) is re-exported from se-domain since prompt 21 |
| `writes::{WriteTool, WriteScene, Planned, NamedItem, run, apply, app_error, EditOutput, summaries}` | Write tools: `WriteTool::plan(scene, input)` → se-app `AgentEdit`s (+ which one creates the item, for batch names); `run::<T>` plans on the current document and applies; `app_error` maps refusals (`REVISION_CONFLICT`, `LOCKED_TRACK`, `*_NOT_FOUND`, `VALIDATION_ERROR`); `WriteScene::{time, duration, item ($name or id), item_kind, tracks, video_track}` |
| `write_inputs::{PositionInput, PointInput, NamedPosition, StrokeInput, AnimationInput, ValueInput, EasingInput, color, span, presets}` | Input pieces shared by write tools (named places, `#rrggbb`, `start` + `end`/`duration`, keyframe values and easings) |

| File | Role |
|---|---|
| `server.rs` | `McpServer`, `mcp_service`, `bearer_token` |
| `registry.rs` | `McpTool` (input type → schema via rmcp's `schema_for_input`, `NAME`, `DESCRIPTION`, `READ_ONLY`, `call`) and `ToolEntry` (definition with annotations + boxed handler parsing the arguments) |
| `context.rs`, `output.rs`, `time_io.rs`, `describe.rs`, `timing.rs`, `writes.rs`, `write_inputs.rs` | Shared plumbing (see above) |
| `analyses.rs` | `AnalysisCache` (stored analyses loaded once per asset per call) and `clips_in` (media clips of a kind of track intersecting a range, with their `ClipWindow`) |

Reads: `get_project_overview`, `get_timeline`, `get_item`, `list_assets`, `get_frames`, `get_source_frames`, `get_audio_analysis`, `get_scene_changes`, `get_transcript` (words of a sequence range in sequence time, segments, word times, paginated), `search_transcript` (full-text search placed where the sequence plays each phrase), `transcribe_media` (ADR-0034: `TranscriptionService::transcribe_and_wait` on the given assets or those of the range's sound clips, waits ≤ 110 s — under Claude Code's two-minute auto-background —, per-asset states; not read-only, not destructive, not scope-limited, not batchable), `list_animation_presets`, `get_brand_kit` (prompt 25: the project's kit or `available: false`), `list_templates` (prompt 24: every template, or one with its source; prompt 25: `source: "library"` and `category`), `get_task_changes`. Writes: `add_text`, `add_shape`, `add_image`, `update_item`, `set_keyframes`, `apply_animation_preset`, `set_volume`, `move_item`, `trim_item`, `split_at`, `delete_items`, `ripple_delete_range`, `insert_gap`, `add_transition`, `add_marker`, `apply_batch` (dispatches to the others' `WriteTool::plan`, `BATCHABLE`). Smart cuts (prompt 22, not batchable: resolved on the current document): `remove_words`, `remove_fillers`, `remove_silences`. Captions (prompt 23): `create_captions` (not batchable: reads the sequence's words through `CaptionService::spoken_words`; style = preset or style id, `CAPTION_PRESETS`), `update_caption_style`, `edit_caption_text`, `emphasize_caption_words` (batchable). `get_item` makes caption word times readable and adds the caption's `caption_style`. Motion templates (prompt 24, ADR-0035): `create_motion_template` and `update_motion_template` (`TemplateCheckService::check` first, then `AgentEdit::CreateTemplate`/`UpdateTemplate`; the check's pictures follow the JSON; not batchable, `create_motion_template` not destructive), `instantiate_template` (brand-bound parameters start from the kit: `se_app::template_library::instance_values`) and `update_template_params` (batchable). Library (prompt 25): `insert_library_template` (reads the entry, then `AgentEdit::InsertLibraryTemplate`; not batchable). Automatic reframing (prompt 26, ADR-0037): `auto_reframe` (waits for the face analyses through `ReframeService::analyses_for` ≤ 110 s — `finished: false` and nothing changed otherwise —, then `AgentEdit::ReframeClips` for the clips of the scope or `AgentEdit::AddReframedVersion` with `target_format`; not batchable). `add_text` starts from the kit's text style; `create_captions` accepts `style: "brand_kit"` |

## Rules and invariants
- One tool per file; tools call se-app use cases (`ProjectService::project`, `MediaService::analysis`/`frame_jpeg`, `FrameRenderService::render`, `AgentEditService::apply`/`changes`…) and never mutate documents. Read tools are annotated `readOnlyHint: true`; write tools `READ_ONLY = false` (destructive); `transcribe_media` `READ_ONLY = false`, `DESTRUCTIVE = false` (it adds transcripts, changes no item).
- Write tools never check the scope themselves: `AgentEditService` checks the whole planned transaction (before and after). They only translate input (times at the task sequence's rate, names, `$name` references, styles) into `AgentEdit`s, purely, and can therefore run alone or inside `apply_batch` unchanged. Keyframe times are relative to the item's start; every other time is sequence time.
- Names of tools, arguments and output fields are `snake_case`; inputs refuse unknown fields (`#[serde(deny_unknown_fields)]`), so typos come back as `INVALID_ARGUMENTS` naming the field. Doc comments of input fields become the schema's descriptions: write them for the agent (default, unit, limit).
- Times cross the boundary as seconds or timecodes (`TimeInput`, `RangeInput`) and leave as `TimeOutput`; flicks never appear in tool I/O, except inside `get_item`'s `properties`, whose flicks fields are rewritten (`readable_time`).
- Outputs stay short: compact JSON, pagination (`offset`/`limit` → `next_offset`) or caps with totals, excerpts of long texts. Every output carries the ids and revisions a later write needs.
- Errors are `ToolError` results (`isError`), never panics; messages say what is wrong and what to do (which tool lists the ids, what exists, the valid range). Only an unknown tool name is a protocol error.
- Default sequence = the task's; default range = the task's range on that sequence, else the whole sequence (`default_range`).
- Tokens are never logged (`server.rs` logs tool, task id, duration and error code).

## Recipe: add a tool
1. Create `src/tools/<tool_name>.rs`: a unit struct, an `Input` (`Deserialize` + `JsonSchema`, `deny_unknown_fields`, doc comments on fields), serialisable output structs, and `impl McpTool` (`NAME`, `DESCRIPTION` saying what it returns and when to use it, `READ_ONLY`, `call`). Read through `context.project()` and se-app use cases; return `ToolOutput::json(&…)` (+ `push_text`/`push_jpeg`) or a `ToolError`.
2. Declare the module in `src/tools.rs` and add `ToolEntry::of::<…>()` to `catalogue()` (bump the counts in its test).
3. Test it: pure parts in-file; behaviour in `tests/tools.rs` over the example project (`tests/support/mod.rs`: `Bed::open()`, `json`, `error_code`, `set_audio_analysis`, `set_scenes`).
4. `INSTA_UPDATE=always cargo test -p se-mcp --test schemas`, review the new `tests/snapshots/schemas__<tool>.snap`.
5. Add its section to `docs/ai-tools.md` (input table, output example, errors) and its row to the catalogue table (`the_catalogue_is_documented` fails otherwise); mention it in `crates/se-app/assets/agent-instructions/` when agents need guidance.
6. A write tool: `READ_ONLY = false`, `call` = `writes::run::<Self>(context, input)`, `impl WriteTool` (its input as `AgentEdit`s; `Planned.creates` names the edit creating its item), add it to `apply_batch`'s `BATCHABLE` and `plan_action` (and to `WRITE_TOOLS` in the catalogue test). A new kind of edit needs an `AgentEdit` variant and its planner in se-app's `agent_edits/`.

## Allowed dependencies
`se-app`, `se-domain`, `se-protocol` (DTOs read through se-app: scopes, presets, error codes), `rmcp` (server + streamable HTTP server), `schemars`, `serde`/`serde_json`, `http` (request parts), `base64` (images), `tokio`, `tracing`. Never another adapter crate. See `docs/architecture.md` §3 and §9.4.

## How to test
- `cargo test -p se-mcp`
- Unit tests in-file: time parsing and output, ranges, lookups, summaries, clip windows and range sets, readable item properties, loudness downsampling, bearer tokens, tool definitions (object schemas, unique names, read-only).
- `tests/tools.rs`: every read tool against the example project opened over se-app's `MediaTestbed` (analyses and transcripts seeded in the fake folder — `Bed::set_transcript` —, frames delivered to the fake renderer link); `get_transcript` maps the interview's words through its sound clip (a word beyond the clip is not played, pages, unsure words, untranscribed media), `search_transcript` finds a phrase with accents ignored and counts phrases the sequence does not play.
- `tests/write_tools.rs`: write tools on the example project (creations with animations, refusal codes, timing tools, keyframes and presets, batches with references and atomicity, `get_task_changes` of a real task via `Bed::run_task`) and the replay of `tests/fixtures/subscribe-pop.json` (`add_text` + `apply_animation_preset`) and `subscribe-pop-recorded.json` (the calls of a real Claude Code run; `{created.N}` placeholders): the item is snapshotted (`snapshots/write_tools__subscribe_pop*_item.snap`), then `RevertTask` restores the initial project. Record new fixtures from the task log (`getTaskEvents`: `toolCallStarted.inputSummary` holds the arguments).
- `tests/cut_tools.rs`: smart cuts on the example project (a transcript and levels seeded): `remove_words` cuts the speech and its linked picture (parts linked), `remove_fillers` with the lists, nothing left, or the agent's words, `remove_silences` on listened tracks and its argument checks, `OUT_OF_SCOPE` for a linked track outside the scope, cuts clipped to the scope's range.
- `tests/caption_tools.rs` (prompt 23): captions created from the transcript with their times and style, a range without speech explained, bad styles and limits refused, text fixes and emphasis in a batch keeping timings, styles changed for some captions (copy), a whole style, and a preset with a field.
- `tests/transcribe_media.rs` (ADR-0034): `NO_TRANSCRIPTION_MODEL` without a model, the sequence's sound media transcribed then readable with `get_transcript` and never transcribed twice, a call with `wait_seconds: 0` (held `FakeTranscriber`) then one that waits, explicit assets (unknown, image without sound).
- `tests/template_tools.rs` (prompt 24): a module checked by the fake renderer (`support::call_with_check` answers the pending check) becomes a template with three pictures and its listing, failed checks and refused declarations add nothing (`TEMPLATE_INVALID` lines), instances with values and keyframes and their refusals, value updates and resets, a batch, a version in place.
- `tests/reframing_tools.rs` (prompt 26): the scope's clips tracked with the given smoothing, a 9:16 version added after the task's sequence at its frame rate with its clips tracked, `wait_seconds: 0` on a held sampler answering `finished: false` with nothing changed, refusals (`INVALID_ARGUMENTS` for a format, a smoothing, empty ids; `VISION_UNAVAILABLE`).
- `tests/library_tools.rs` (prompt 25): library templates listed by category with the project's copy, inserted with the kit's values and given values (copy reused), refusals; a project without kit (`available: false`, `add_text` in Inter). `tests/tools.rs` reads the example's real kit.
- `tests/schemas.rs`: insta snapshots of every tool definition (`tests/snapshots/`) and a check that `docs/ai-tools.md` has a section per tool.
- The HTTP side (token guard, real rmcp client, images) is tested in se-core (`src/mcp_routes.rs`).
