# se-app

## Purpose
The application layer: use cases, ports (traits implemented by adapters), the `ProjectActor` (single writer of a project, owner of AI changesets), the `JobQueue` and the media use cases, the AI `TaskService` (the architecture's `TaskScheduler`, prompt 17, ADR-0027) and the `AgentEditService` (edits of AI agents, prompt 19, ADR-0029). It orchestrates; it never performs concrete IO.

## Rules and invariants
- No `std::fs`, `std::process` or network access: IO only through ports.
- Only `ProjectActor` mutates a `Project`, by committing `Transaction`s. The service never edits a document: it sends transactions (a temporary actor, events discarded, for closed projects). Building a new document (create, duplicate) is not a mutation.
- Commit flow (ADR-0017): `commit` on a draft → `append_journal` → install, record history → publish `projectPatched` then `historyChanged` → schedule the snapshot. A journal failure must leave state and history untouched (undo/redo restore the cloned history).
- Delays use tokio's timer (testable with `start_paused`); timestamps stored with data use the `Clock` port.
- The registry mutex (`ProjectService::open`) is held for the whole of open/close/rename/duplicate/trash; edits only clone a handle.
- Labels of transactions built here (`sequence_labels`, `Rename project`, `track_labels`, `marker_labels`, `item_labels`, `media_service::labels`) are stable identifiers translated by the renderer (`apps/desktop/src/app/editor/history-label.ts`): change both sides together.
- Item edits are planned with `EditPlan`: read the draft with `plan.project()?` (it applies the queued operations), queue with `plan.push(op)`, commit with `commit_plan` (nothing when the plan is empty). Ripple edits shift the **concerned tracks** (edited tracks + unlocked tracks holding items linked to what moves) and refuse to remove time over other content (`RippleBlocked`); overwrite placement clears ranges on the target tracks only (ADR-0021). The renderer previews these rules (`apps/desktop/src/features/timeline/services/ripple-preview.ts`): change both together.
- User actions are `Actor::User` transactions (undoable); facts the app observed (missing media at opening, decodability reports) are `Actor::System` transactions (journaled, never undone). Skip system commits that change nothing.
- Thumbnails and peaks are cache (`<project>/cache/media/<cache key>/`), never recorded in the document: the media service queues the outputs that are missing when a project opens and after an import or relink (ADR-0018).
- Mezzanine and proxy states live in the document (`Asset.derived`), changed only by system transactions: `pending` when queued, `ready`/`failed` by the job's `DerivedRecorder`, which changes nothing unless the asset still waits for that very file (ADR-0019). Patch one derived copy or summary per field (`AssetPatch::{mezzanine, proxy, audio_analysis, scene_detection}`), never the whole `DerivedMedia`.
- Scheduling (`media_service/scheduling.rs`) is idempotent: `schedule_asset(handle, project, asset, Trigger)` after imports, relinks, decodability reports, settings changes (open projects) and at opening/cache cleanup (`Trigger::Opening` also retries failed copies). Analyses run once per content key (`AnalysisStore`).
- Observers run while the project registry is locked: they must never call back into `ProjectService`. A project's jobs are cancelled before it closes.
- Every port has an in-memory fake behind the `test-support` feature so use cases are tested without IO.
- CPU-heavy work goes to `spawn_blocking`.
- AI edits go through `AgentEditService` only, as `Actor::AiTask` transactions committed with `apply_ai_on` (never `apply`): the actor records them in the task's changeset in the same atomic write as the journal. Their scope is checked on the planned transaction before and after; never commit an AI transaction whose scope was not checked on the base it is applied to.
- AI runs act only through the MCP endpoint of their spec: a run's token is valid exactly while the run is going (minted after it is marked running, revoked by a drop guard whatever way it ends).
- AI tasks: task state lives behind the service's async mutex, held while a change is saved (saves of one task never overtake each other); event appends happen outside it. Every task change is saved then published (`taskUpdated`); every event appended then published (`taskEventAppended`). A run's status and its task's are always equal (`task_state::set_status`). Nothing reruns a task without the user: interrupted tasks only fail.

## Allowed dependencies
`se-domain`, `se-protocol`, `tokio`, `async-trait`, `tracing`, `thiserror`. Never an adapter crate. See `docs/architecture.md` §3.

## How to test
- `cargo test -p se-app`
- Unit tests in-file (patch building, recovery, new projects, error codes).
- `tests/project_actor.rs`: actor against the in-memory store with `#[tokio::test(start_paused = true)]` (commit order, events, journal failure, debounced and retried snapshots, close).
- `tests/project_service.rs`: use cases against the fakes (create, open with replay, locks, copies, close, rename open/closed, duplicate, trash, missing folders, undo/redo).
- `tests/timeline_edits.rs`: track and marker use cases (names of new tracks, reordering, locked tracks, labels, one undo step each).
- `tests/item_edits/` (`support.rs` opens the example project reduced to V1, V2, A1 over in-memory ports; `graphics.rs`: graphics on the highest free track or a new one on top in one step, image assets only, presets on several items in one step, refused for items lacking a property, several properties in one step; `sequences.rs`: a 9:16 version independent of its source with filling clips and narrowed texts, plain duplicates, format changes in one undo step, the frame rate locked once items exist, renames, the last sequence kept, a reframe mode and its compensating scale in one step; `sound.rs`: transitions shortened to their cut, refused without room, resized and realigned, kept when both items move, removed with one moved away, fades and volume curves — one undo step each): dropped media (linked picture and sound, new tracks), moves (overwrite, insert pushing linked tracks), copies and pastes, ripple trims, splits keeping right parts linked, deletes with and without ripple, links, gap resizes (blocked over other content, a locked partner track left out), locked tracks never changed — each one undo step. Planner unit tests live in `src/edit_plan/*.rs`.
- `tests/job_queue.rs`: the queue with scripted `JobWork` (priorities and per-kind slots, retry then failure, cancelling queued and running work, closing a project, progress throttling). Let spawned tasks run with a few `yield_now`.
- `tests/frame_renders.rs`: the frame render service over `FakeRendererLink` (uploads in any order answer in time order, refused uploads, reported failures, a timeout with `start_paused`, no renderer, too many frames, a dropped caller forgotten).
- `tests/agent_edits.rs`: `AgentEditService` over the example project with real tasks (replayed runs): the scope matrix (inside, outside after, straddling before, creations, ripple edits in a time-limited scope, forbidden tracks, graphics on the task's tracks), linked partners following moves and deletes, atomic calls naming their failing edit, stale revisions, reverts (project restored, `changesetId` cleared, `NothingToRevert`, undo of the revert), conflicts with a user edit, active tasks refused, changesets surviving a reopening.
- `tests/task_service.rs`: the task service over `MediaTestbed` (also: each run's MCP token resolves to its context while it runs and is revoked after; follow-ups get new tokens; cancelled runs lose theirs) with `#[tokio::test(start_paused = true)]` and `run_for(ms)` (a paused-clock sleep lets runs progress): 5 tasks with a limit of 3 (3 running, 2 queued, FIFO), cancelling running (agent killed) and queued tasks, follow-ups resuming the session, retries (fresh session after a failed first run), events saved and published in order, interrupted tasks after a "crash" (a second testbed fed the folder's tasks), closing a project, refusals while missing or logged out, a logged-out run correcting the status, start/workspace failures and silent agents, settings, scope checks. Unit tests in `src/tasks/*.rs` and `src/ports/agents.rs`.
- `tests/media_service.rs`: media use cases through `MediaTestbed` (import with failures and jobs, duplicates, cached outputs, missing on reopening + relink, other content needs `force`, relinking through the relative hint after a move, decodability as system transactions, undoable removal, jobs stopped at closing).
- `tests/derived_media.rs`: ProRes → pending then ready mezzanine (HEVC with capabilities) and proxy; decodable 1080p H.264 gets neither; automatic proxies for UHD, off by setting, on request at 720p; refusals (`DERIVED_NOT_APPLICABLE`); a failed mezzanine kept with its reason, retried on request and on reopening; analyses stored once per content with summaries, cleared by a relink to other content; cache cleanup regenerating derived files but not analyses; settings validation and the tools folder; frame extraction cached, out-of-range times refused.
- `media_policy` decision tables are unit tests in `media_policy/mezzanine.rs` and `proxy.rs`.
- Integration tests reach the fakes through the self dev-dependency with `test-support`.
