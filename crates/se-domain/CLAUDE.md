# se-domain

## Purpose
The pure document model of SimpleEffect: time in flicks, identifiers, projects, sequences, tracks, items, keyframes, validation, and every change of a document: operations with exact inverses, transactions, the user's undo/redo history and AI-task changesets with conflict-aware reverts (ADR-0005, ADR-0016). It is the single source of truth for document types (exported to TypeScript through ts-rs). It does **not** persist, schedule, render or talk to anything: the `ProjectActor` of se-app (prompt 07) owns the project and calls `commit`.

## Layout
- `animation_preset/`: `definition.rs` (library types and `check`), `expansion.rs` (`expand_preset`: span, base, merge, exit mirroring); the library is parsed once (`LazyLock`).
- One concept per file: `time/*.rs`, `document/*.rs`, `validation/*_rules.rs` (one family of rules each, with one test per code in the same file), `operation/*.rs` (one operation or small group each, with its unit tests), `reformat/{adaptation,copy,plan}.rs`.
- `validation/report.rs` holds the shared plumbing (`Path`, `Report`, `ProjectIndex`, `seconds()` for messages).
- `operation/` plumbing: `effect.rs` (`Edit` trait implemented by every payload, `Effect` = inverse + touched, `run_steps` for composite edits), `lookup.rs` (find entities by id), `checks.rs` (locked track, revision, overlap, unused id, names, indices, `swap_field` for inverse patches), `placement.rs` (`place_item`, `insert_new_item`, `remove_item`: the only code that moves items between tracks), `reshape.rs` (retiming every animatable property's keyframes through `AnimatableProperty::ALL`, fades and source of a trimmed or cut item), `transition_ops.rs` (add/update/remove), `transition_upkeep.rs` (dropping the transitions an item move breaks, `TransitionSnapshot` and the restoration ending composite edits), `testing.rs` (unit-test helpers, `cfg(test)`).

## Rules and invariants
- Pure: no IO, no async, no clock, no randomness, no process spawning, no logging side effects.
- Time is always `Flicks`; never floats for positions or durations. Use the conversion helpers of `time`.
- **Single-value invariants live in the value types** (private fields + validating constructor + validating `Deserialize`): `Flicks` range, `TimeRange` duration, `FrameRate`, ids, `Color`. **Cross-entity invariants live in `validation`** and are reported, never panicked on. A new invariant goes in one of the two, with a test per violation code.
- Serde conventions: `rename_all = "camelCase"`; enums with data `tag = "kind"` (+ `rename_all_fields = "camelCase"` when variant fields have several words); unit enums as camelCase strings; `None` as `null`. Validated types implement `Deserialize` by hand (ts-rs ignores and warns about `#[serde(try_from)]`). Patches sent by clients (`TrackPatch`, `MarkerPatch`) add `#[ts(optional_fields)]` so TypeScript may omit unchanged fields (`#[serde(default)]` reads them as `None`).
- Every serialized type derives `ts_rs::TS`. Types not reachable from `Project` or `Violation` need a root in `crates/se-codegen/src/bindings.rs`. Run `pnpm codegen` after any change; never hand-edit the generated TypeScript.
  Operations, transactions and changesets derive `TS` but have no root: the renderer receives whole entities, never operations (ADR-0005). `Conflict` is exported through `TaskRevertReport` (prompt 19).
- The insta snapshot `src/document/snapshots/*example_project_json_format.snap` fixes the `project.json` format. If it changes, the format changed: think about schema migration (prompt 07) and the renderer, then accept it (`INSTA_UPDATE=always cargo test -p se-domain`).
- Messages of errors and violations are read by users and AI agents: say what is wrong and how to fix it, quote values, write times with `seconds()` (violations) or `error::clock()` (`HH:MM:SS.mmm`, domain errors).
- `apply` validates the result (`validate_project`, so it needs a valid input) and never changes revisions. `commit` (and `apply_all`) validates **once, after the last operation**: each operation checks its own preconditions, but a transaction may pass through states only its later operations repair (ADR-0021; validating after every operation cost a full validation per operation). `commit` bumps the project revision and the touched items' revisions once per transaction. Revisions only grow.
- Every operation records its exact inverse: item edits record `RestoreItem` of the previous state (via `place_item`), additions `RemoveItem`, removals `AddItem`/`Add*` at the same index. Composite edits build primitive steps with `run_steps`, ordered so that every intermediate state is valid (`place_item` refuses transient overlaps; the inverse replays them backwards).
- Ids of new entities are always inputs (`newItemId`, `splitIds`, payload ids): never generate ids here.
- Track items stay sorted by start (`placement::insert_sorted`); never push onto `track.items` directly.
- **Every animatable property goes through `AnimatableProperty`** (ADR-0025): never reach `style.font_size` & co. for keyframe logic directly. A new property needs a variant (+ `ALL`, `name`, `allowed_range`), its slot in `ItemKind::property`/`property_mut`, its JSON path in `validation/animation_rules.rs::property_path`, a line in `property_animations!` and the renderer mirror (`apps/desktop/src/shared/animation/property-access.ts`).
- **The domain never interpolates** (the engine does): presets read existing keyframes as holds (`Animatable::held_value_at`).
- **Format changes are planned, not operations** (ADR-0026): `format_change` builds ordinary operations (their inverses undo the change exactly) and `sequence_version` builds a new sequence for `AddSequence`. The frame-rate lock lives in these planners only, never in `UpdateSequence` (undo must always work). Ids of copies come from the caller's `SequenceIds`.
- **Transitions follow their items** (ADR-0024): `place_item`/`remove_item` drop the transitions of the touched item that no longer fit (recording an `AddTransition` after the item's inverse); an operation made of steps that may separate and rejoin items (split, ripple delete, insert gap) snapshots the transitions first and ends with `restore_transitions` (inverses first). A new composite operation moving items must do the same. Transition operations never check fit themselves: validation does, at the end of the transaction.

### Recipe: add an operation
1. Create `src/operation/<name>.rs` with a payload struct (`Serialize`, `Deserialize`, `TS`, `rename_all = "camelCase"`, doc comment stating what it does and its inverse) and `impl Edit`: check preconditions with `lookup`/`checks` (unknown id, locked track, `expected_revision`…), mutate through `placement` for items, call `effect.undo_with(…)` with the exact inverse and fill `effect.touched`.
2. Add the variant (with a doc line) to `Operation` and the name to `operation_payloads!` in `src/operation.rs`; re-export the payload in `operation.rs` and `lib.rs`.
3. New refusal → a `DomainError` variant with an actionable message and its `DomainErrorCode`.
4. Unit tests in the file with `operation::testing::apply_ok` (asserts a valid result and an exact inverse) and `apply_err`; add a case to `tests/operations/generators.rs` (bump `KINDS`) so the property tests cover it.
5. Update `docs/architecture.md` §5.4; the journal snapshot (`src/snapshots/*transaction*`) changes only if an existing operation's format changes (stored journals then need a migration, prompt 07).

### Animation preset format (`assets/animation-presets.json`)
```json
{ "version": 1, "presets": [
  { "id": "slideFromLeft", "name": "Slide from the left", "description": "…",
    "phases": ["in", "out"], "defaultDurationSeconds": 0.6,
    "tracks": [
      { "property": "position", "keyframes": [
        { "at": 0, "value": { "offset": [-0.1, 0] }, "easing": { "kind": "cubicBezier", "x1": 0.16, "y1": 1, "x2": 0.3, "y2": 1 } },
        { "at": 1, "value": "base" } ] } ] } ] }
```
- `phases`: `["in", "out"]` (written as the entrance; the exit plays it backwards: `at` → `1 − at`, order reversed, each segment's easing mirrored) or `["emphasis"]` (returns to `base`).
- `at`: position in the span, strictly increasing within `[0, 1]`; at least two keyframes per track. `easing`: the domain's `Easing` JSON (linear when absent), leaving that keyframe.
- `value`: `"base"` (the item's value: at the span's end for an entrance, its start for an exit or emphasis, keyframes read as holds), `{"absolute": v}`, `{"offset": v}` (base + v), `{"factor": v}` (base × v, per component). `v` is a number (both components for pairs), `[x, y]` or, for colour properties, an absolute `"#rrggbb"`. Positions are normalised in the frame, sizes design pixels.
- Ids are stable (operations, agents, the renderer's translations `editor.animations.presets.<id>`): add presets, never rename one. `library.check()` runs at load and in tests; `animation_preset::tests` snapshots every expansion (`src/snapshots/*preset_samples.snap`): review it when changing the library.

## Allowed dependencies
No workspace crate (innermost layer). Third-party: `serde`, `serde_json` (the embedded preset library, lenient `Animatable` reads), `thiserror`, `uuid`, `ts-rs` (derive only). Dev: `proptest`, `insta`. See `docs/architecture.md` §3.

## How to test
- `cargo test -p se-domain` (unit tests see `test_support` through `cfg(test)`; no feature needed).
- Unit tests in-file under `#[cfg(test)]`; validation tests mutate `test_support::example_project()` and expect exactly one code.
- `tests/captions.rs` (prompt 23) runs `docs/test-vectors/caption-lines.json` (also run by the engine's `caption-layer.test.ts`) and checks with proptest that segmentation keeps every word once in valid captions within the line limits, that edited texts give one valid word per token, that substitutions keep every timing, and that splitting between words then merging gives the words back.
- `tests/transcript_mapping.rs` runs `docs/test-vectors/transcript-mapping.json` (also run by the renderer's `shared/transcript/sequence-words.test.ts`: change both sides together) and checks with proptest that any cuts and speeds keep words sorted, inside their clips and unique.
- `tests/test_vectors.rs` runs `docs/test-vectors/flicks.json` and `timecode.json` (also used by the TypeScript time helpers of prompt 10: change both sides together).
- `tests/time_properties.rs`: proptest (frame round trips at every standard rate, `TimeRange` algebra, timecode round trips).
- `tests/operations/` (1000 cases each): random operations from `generators.rs` (incl. reframe patches and focus keyframes) keep projects valid and invert exactly; `reformat.rs` (500 cases): after random edits, format changes with any policy stay valid and undo exactly, versions are valid and share no id with their source; undo/redo walk through the same states with growing revisions; an undisturbed changeset revert restores the project; `multi_cut.rs`: after random edits, a `RippleDeleteRanges` gives exactly the project of the same single ripple deletes applied from the last range. `every_operation_kind_succeeds_sometimes` guards against a vacuous generator.
- Integration tests reach `test_support` through the self dev-dependency with the `test-support` feature (`Cargo.toml`).
- Other crates' tests enable the `test-support` feature in their dev-dependencies to reuse the example project and deterministic ids.
