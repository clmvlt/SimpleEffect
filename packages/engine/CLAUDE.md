# @se/engine

## Purpose
The rendering engine shared by preview and export (WYSIWYG, `docs/adr/0002-web-rendering-engine.md`, `docs/adr/0022-rendering-engine-evaluation-decoding-compositing.md`, `docs/adr/0023-playback-audio-clock-and-av-sync.md`): document evaluation at a time, WebCodecs decoding (via Mediabunny), PixiJS compositing, real-time playback on the audio clock with the Web Audio graph, and the export Worker (ADR-0038). It has no UI.

Implemented progressively: capabilities (prompt 08), playback sources (09), evaluation/decoding/compositing/preview (12), playback and audio (13), motion templates (24, ADR-0035), export (27).

Data flow: `FrameRenderer.render({ scene, time, proxy, playback? })` → `evaluate` → for each picture layer `chooseVariant` + `MediaLocator` → `DecoderPool.peek*` (sync) or `videoFrame`/`image` (async, cancellable; `playbackFrame` waits for the clip's sequential reader) → `Compositor.render(graph, pictures)` → leases released.

Playback flow (ADR-0023): display refresh → `PlaybackController` reads the master clock (`audioContextClock`), computes the frame at the next refresh, reports it (`onFrame`) → the app moves the playhead → `PreviewEngine.setTime` (playback mode) prefetches (`prefetchSpans` → `DecoderPool.prefetch`) and draws at once when cached. The controller's transport goes to `AudioEngine.setTransport` → `AudioScheduler` (25 ms `setInterval` ticks) plans the pieces starting in the next 200 ms (`playbackSegments` + `planPieces`) from chunks decoded 2 s ahead.

## Rules and invariants
- No React, no `@se/ui`; no network calls except to se-core (`/media`). Preview and export use the same code path (`FrameRenderer` + `Compositor`).
- `evaluate` and everything in `animation/` are pure (no clock, no IO, no globals). Time is flicks; seconds appear only at the decoder boundary (`frameLookupTime`).
- **Frame lifetimes.** The `DecoderPool` owns every `VideoFrame` and `ImageBitmap`: it adopts them into the `FrameTracker` when decoded and closes them through it. Everyone else **leases** (`PictureLease.release()` exactly once, extra calls ignored). The cache never closes a leased picture; removed ones close on their last release. `Compositor.render` must upload pictures before returning and keep no reference that it could read later (Pixi texture sources use `autoGarbageCollect: false` and are re-pointed on the next render). Pixi never closes resources. Destroying a pool closes everything not leased.
- Cache limits matter: hardware decoders stall when too many decoded frames are held (default 48 pictures, 256 MiB).
- Pictures are cached by source **and URL**; a changed URL (relinked file, regenerated proxy, restarted core) is new content.
- A picture's box comes from the asset (`assetDisplaySize`), never from the decoded frame: originals, mezzanines and proxies fill the same box.
- Media time 0 is the first frame (`max(0, first timestamp)`). Ask for frames with `frameLookupTime(sourceTime, assetFrameRate)` (mid-frame), never with raw seconds.
- Always check decodability before decoding (`track.canDecode()` in `MediabunnyVideoSource`; `capabilities/` for imports); fall back to mezzanines (`chooseVariant`).
- `pixi.js/unsafe-eval` stays imported first in `pixi-compositor.ts` (the renderer's CSP has no `unsafe-eval`).
- Error messages never contain media URLs (they carry the session token).
- Shared interpolation vectors (`docs/test-vectors/interpolation.json`) are the contract with a future Rust evaluator: change them only with the code.
- **Clock.** The master clock is the audio clock (`audioContextClock`: the context time being *heard*, `getOutputTimestamp` interpolated, never ahead of `currentTime`, monotonic). Positions always come from the transport anchor and the clock (`transportPosition`), never from accumulated deltas. New anchors take effect `leadTime` ahead (output latency + 30 ms) so sound starts on its first sample. Without Web Audio the app passes a `performance.now()` clock (silent playback).
- **Playback frames.** Late frames are skipped (`skippedFrames` counts those beyond what a fast speed skips anyway); a frame still decoding is never superseded during playback (the latest time is drawn after it); the frame chosen is the one for the next display refresh (`RefreshPeriod`).
- **Playback decoding.** Sequential readers are bounded by a read-ahead budget in frames **and bytes** (`DecoderPool.readAheadBudget`), and forward playback closes the frames every clip reading that file has passed (`FrameCache.dropPassed`, per shown stretch: a frame one clip passed may be ahead of another clip of the same file): open frames stall hardware decoders, and a 1080p frame is 8 MB of a 256 MiB cache. Readers stop when no longer requested (`prefetch([])` on pause).
- **Scheduling.** Audio is scheduled from a 25 ms timer, 200 ms ahead (`SCHEDULE_AHEAD_SECONDS`); a piece is scheduled in the window where it starts and plays to its end (never cut mid-chunk); start times are computed from the segment anchor (sample-exact over any duration); any transport change stops all voices and plans again; unchanged clips (`sameClips`) keep scheduled sound. Sound plays at rate 1 only.
- **Chunks.** One second of media time per chunk; buffers placed contiguously unless a real gap shows; each chunk continues the previous chunk's placement (decoded in order per file); media time 0 of the sound is the first video frame when the file has video. Audio reads the original or the mezzanine, never the proxy.
- **Fades and levels** (ADR-0024). `fadeCurve` is the only implementation of the domain's fade shapes, used for picture opacity and sound gain; levels beyond an item's edges hold the edge value. Volume is interpolated in decibels, then converted (`dbToGain`). Each voice gets a `gainEnvelope` (one point when constant, else points every 10 ms) that the graph only ramps between: compute levels in pure code, never in the graph.
- **Texts** (ADR-0025). A text layer is laid out once on the whole text without outline or shadow (`CanvasTextMetrics`), then drawn line by line at aligned places (`lineOffset`); a reveal shows the first characters (grapheme clusters) without moving them. Outlines are drawn twice the requested width centred on the glyph outline (the width shows outside); a disabled outline is a zero-width stroke. The node caches its style and layout keys: unchanged texts are not re-rasterised. Its box (plate included) is what `render` returns.
- **Captions** (ADR-0033). A caption layer is laid out word by word from the plain words (`captionLayout`): colours (active word, karaoke fill, emphasis), pops and reveals never move a word; lines break greedily by characters exactly like the core (`captionLines`, shared vectors) and only the page holding the active word shows. Plates: one behind the block, or one per line with `boxPerLine` (a small gap apart, never overlapping). Captions without a style in the scene use the default preset.
- **Fonts.** Text frames wait for the catalogue's faces (`FontLoader.ensure`, at most `FONT_LOAD_TIMEOUT_MS`) before drawing; families the catalogue lacks are drawn with `FALLBACK_FONTS` (Inter, the UI's Inter Variable, sans-serif) and reported. Never draw text before fonts are settled in export.
- **Reframing** (ADR-0026). `reframedPicture` is the only computation of a clip's box: `fit` fits the picture, `fill`/`tracked` give the frame as box and a `crop` of the upright picture around the focus (clamped inside it), `custom` the natural size in design pixels. `PictureNode` frames its texture on the crop mapped to the decoded pixels by `codedCrop` (undo the mirror, then the display rotation). Golden tests check a crop against the same view placed by hand (custom mode + transform), for plain and rotated footage.
- **Safe areas** are data for the viewer's overlay only: never drawn by a compositor, never exported. Each JSON file states its source and measurement date; re-check them when platforms change their interface.
- **Blur** is a Pixi `BlurFilter` on the layer's root, attached only while the radius is visible (filters render offscreen).
- **Dissolves.** `evaluate` lists the two sides of a cross dissolve one after the other with their `dissolve` role and weighted opacities; a compositor must draw them as one isolated group with the incoming side added (`DISSOLVE_COMPOSITING`), never as two ordinary layers.
- **Motion templates** (ADR-0035). A template layer's picture comes from the `TemplateRenderer` given to the `FrameRenderer` (`TemplateRuntime` in the app), never from the module directly; frames are leased like decoded pictures and cached by template, version, values, size and instant. Template code runs **only** in its Worker: everything under `templates/sandbox/` is serialized with `toString()` into the Worker's source, so those functions must be self-contained (only their parameters and JavaScript built-ins: no import, no outer variable, no helper from another module) and nothing may be declared at the script's top level. `contract.ts` types the messages; the Worker side cannot import them: keep both sides in step by hand. A blob Worker inherits the page's CSP (no `unsafe-eval`): never generate code inside it. Sizes in the drawing API are design pixels (shorter side 1080), scaled to the output; shadows and blurs too. A failing or overrunning template gives the error picture and a `TemplateIssue`, never a broken frame. Checks render twice (warm-up, then timed) so first-use costs never count against the 50 ms budget. **Fonts in Workers:** Electron's Chromium keeps the fallback font for a family a Worker used before its faces arrived, even after they load (per Worker, not per canvas): give families *before* the first frame using them. Workers start with Inter and the families their version is known to use; a frame reporting `missingFamilies` the catalogue has makes the pool start a new Worker given them first (`TemplateWorkerPool.restartWithFonts`, the old one `retire`s after its queued frames) and the frame is drawn again there; checks do the same (a second Worker). A Worker the app stopped fails as `unloaded` (never marked failed: the frame is drawn again in the current Worker). The test browser does not show the bug: tests count Workers.
- **Export** (ADR-0038). The export draws with the preview's `FrameRenderer`, compositor, fonts and template runtime (golden rule 7), from the snapshot the core sent, never the mirror. Frames are drawn in order in playback mode and never skipped (a frame waits for its pictures); originals or mezzanines only (`exportMediaLocator` refuses proxies). Video encoders prefer hardware and fall back to software (`videoEncodingConfig`); ProRes and DNxHR are never encoded here (`webCodecsVideoCodec` → `null`: RGBA frames for ffmpeg after the WAV of the sound). Sound is mixed on the page (Workers have no `OfflineAudioContext`) in `AUDIO_BLOCK_SECONDS` blocks through the preview's `AudioGraph` with the same gain envelopes, each rendered from a lead-in so blocks join on the sample: never change the graph for export only. Uploads go through `httpExportSink` in `UPLOAD_CHUNK_BYTES` at explicit positions (muxers patch headers); a refused upload's error never includes its URL (`withoutUrls`). Cancelling terminates the Worker, which frees decoders, the GPU context and uploads. The app's renderer bundles the Worker as an ES module (`worker.format: 'es'` in `electron.vite.config.ts`).
- **Meter worklet.** `meter-processor.ts` runs in the AudioWorklet scope: pure imports only (it is bundled alone with `?worker&url`), no allocation per block. A failed `addModule` leaves the meter silent, never the sound.

- **Performance** (prompt 29, `docs/performance.md`). Scrub budget 100 ms (95th percentile): 4K long-GOP originals cannot meet it (~550 ms from the previous keyframe), which is why the viewer reads ready proxies by default; never make the preview read originals when a proxy is ready unless the user turned proxies off. `PreviewEngine.settled()` resolves when the current frame is drawn (used by the in-app measure); drawing happens on animation frames, so a hidden window draws nothing.

## Known limits (playback)
- Sound plays only at 1× forward; JKL 2×/4× and reverse are silent; clip speed changes pitch.
- Timers are throttled in a hidden or minimised window: playback stutters there (backlog).
- Reverse playback reads chunks of the window before the playhead: long-GOP footage skips frames.
- Volume curves, fades and cross-fades are heard at 1× only (like all sound).
