# @se/desktop

## Purpose
The Electron application: the main process supervises se-core and manages windows; the preload exposes a minimal typed bridge; the renderer is the React app. No business logic in `electron/`: the core owns the document, and the renderer sends commands to it.

## Public API
- `electron/shared/bridge-api.ts`: the contract shared by main, preload and renderer (`CoreConnection`, `ChooseFolderOptions`, `ChooseFilesOptions`, `SimpleEffectBridge`, `IPC_CHANNELS`). Its tsconfig has the DOM lib (`File`).
- `window.simpleEffect.getCoreConnection()`: resolves with `{ url, token, version }` of the running core, waiting while it (re)starts. `CoreClient` calls it before every connection attempt (a restarted core has a new port and token).
- `window.simpleEffect.chooseFolder({ title, buttonLabel, defaultPath? })`: native folder picker (absolute path or `null`); `chooseFiles({ title, buttonLabel, filterName, extensions, allFilesName })`: native multi-file picker (absolute paths, empty if cancelled); `showInFolder(path)`: reveals a file or folder in the OS file manager; `getPathForFile(file)`: absolute path of a `File` dropped from the OS (`webUtils.getPathForFile`, empty for files not on disk). Renderer code reaches the bridge through `useDesktopBridge()` (`src/shared/desktop/`), never `window` directly (except `main.tsx`).
- Renderer code talks to se-core only through `src/shared/core/` hooks and `@se/protocol` types: `useCoreClient().send({ kind: 'getCoreInfo' })` resolves with the typed result.

## Rules and invariants
- Security: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`; the CSP (meta tag written by `tooling/csp-plugin.ts`) only allows scripts from the bundle and connections to `127.0.0.1` in production; inline `<style>` elements are allowed for Radix and sonner (ADR-0013).
- UI: components, icons (`@se/ui/icons`) and toasts come from `@se/ui` only; ESLint rejects imports of `radix-ui`, `lucide-react`, `sonner`, `class-variance-authority` and `react-resizable-panels` here. Style with token utilities (`bg-panel`, `text-text-muted`…): the default Tailwind palette does not exist and raw colours fail `pnpm check`.
- The session token is never logged (the supervisor logs the URL and version only).
- Features import each other only through their `index.ts`; `shared/` never imports features or `app/` (enforced by `eslint-plugin-boundaries` in the root `eslint.config.js`).
- Keep hooks thin: put connection logic in plain functions taking a `CoreClient` (or a `Pick` of it) so it is testable in Node (see `watch-core-info.ts`).
- Components hold no business logic; every user-visible string goes through i18n (`useTranslation()` → `t('area.key')`). ESLint (`i18next/no-literal-string`, mode `jsx-only`) rejects JSX text and literal `aria-label`, `title`, `placeholder`, `label`, `description`, `content`, `alt`, `*Label`… in `src/**/*.tsx` (tests exempt; digits/punctuation and CAPITALS allowed). Pass `@se/ui` widgets their labels from `t()`, overriding their English defaults.
- Routing: React Router in library mode with a **hash router** (the renderer is a file in production). Add a screen as a route object in `app/routes.tsx`; inject what it needs through `AppRouteDependencies`.
- The project store is read-only for features: read with `useProjectSelector(selector)` (selectors return stored references, never new arrays), change the project by sending a command to the core; the patch updates the store. Only `app/editor` loads and forgets the project (`useProjectSync()`).
- Every error shown to the user is translated by code: `t(errorMessageKey(error))`. A new protocol code needs `errors.<CODE>` in `fr.json` and an entry in `ERROR_CODES`.
- Keyboard shortcuts are named actions: add an entry to `SHORTCUT_ACTIONS` (contexts, default keys, `repeats`) and its label `shortcuts.actions.<id>` in `fr.json`, then bind it with `useShortcutAction(id, run)`; never listen to `keydown` for commands. A panel with its own shortcuts wraps its content in `ShortcutRegion context="…"`. Shortcuts never fire inside inputs, textareas, selects or editable content, and the default table must stay free of conflicts (tested).
- The timeline's view state (zoom, scroll, in/out, playhead, track heights, active sequence, snapping) is a machine preference saved per project in `localStorage` (`timeline-persistence.ts`), never project data; track and marker edits are protocol commands (one undo step each).
- Timeline gestures (ADR-0021): while the pointer drags, a controller writes only the ephemeral `gesture-store` preview (never a command, never the mirror); on release it sends **one** command (one transaction) and clears the preview once the command resolved (the patch arrives first) or failed (toast). Computations stay pure in `services/`; the core decides (it re-validates everything and may refuse, e.g. `RIPPLE_BLOCKED`). New gestures plug into `use-lane-pointer.ts`, which reads elements by `data-item-id`, `data-trim-edge`, `data-gap-handle`. Edges move by whole frames and snap through `snapEdges` (`hooks/gestures/gesture-context.ts`).
- Canvases read design tokens with `tokenValue` from `shared/canvas`, never `getComputedStyle` per draw (it forces a style recalculation: the timeline's main zoom cost before the cache).
- Panel sizes are machine preferences (`uiPreferencesStorage()`), never project data. Dock `layoutId`s are a compatibility surface: renaming one resets users' sizes.
- `__APP_VERSION__` (from `package.json`) is injected by Vite `define` in `electron.vite.config.ts` and `vitest.config.ts`.
- All runtime dependencies are bundled by electron-vite, so they are `devDependencies` and the packaged app ships no `node_modules`.

## Allowed dependencies
`@se/protocol` (renderer; type imports only in `electron/`), `@se/engine`, `@se/ui` (renderer only), React, Zustand. Electron APIs only in `electron/`. See `docs/architecture.md` §4.

## How to add a translation key
1. Add it to `src/i18n/locales/fr.json` under its area (`editor.timeline.zoomIn`), in French, with typographic apostrophes (’) and ellipses (…).
2. Use it: `const { t } = useTranslation(); … t('editor.timeline.zoomIn')`. Interpolation: `"version": "Version {{version}}"` → `t('statusBar.version', { version })`.
3. `tsc` fails on an unknown key; `create-i18n.test.ts` fails on an empty value.

## How to test
- `pnpm vitest run --project desktop` (or `pnpm test` at the root): `electron/**/*.test.ts`, `tooling/**/*.test.ts`, `src/**/*.test.{ts,tsx}`. Tests run in Node; a test that renders React starts with a `/** @vitest-environment jsdom */` docblock (`vitest.setup.ts` adds jest-dom matchers, cleanup and jsdom stubs).
- Shell tests (`src/app/app-shell.test.tsx`) render `AppProviders` + a memory router from `createAppRoutes`, with a real `CoreClient` whose endpoint never resolves (stays « connecting », opens no socket), an idle bridge, a project store preloaded with `shared/project-store/testing/session-fixture.ts` for editor routes, and an in-memory layout storage. Inside docks, drive tabs with the keyboard: in jsdom the panel library takes clicks for resize grabs.
- Logic taking the core client is tested with small fakes of `send`/`on` (`project-sync.test.ts`, `load-editor-project.test.ts`, `media-bin/hooks/hooks.test.ts`); dialogs take their effects as props (`NewProjectDialog.test.tsx`).
- Editing tests (`TimelineEditing.test.tsx`) use `testing/render-timeline.tsx` (`renderTimeline()` → `{ send, lanes }`, `send` answering every command, `itemElement(id)`, `resetTimelineStores`): drags are `pointerDown` on the item/handle then `pointerMove`/`pointerUp` on the lanes (lane pixels = client pixels, 50 px per second); jsdom has no `DragEvent`, so drops set `clientX`/`clientY` on a `createEvent.dragOver/drop` event; wait for a gesture's async end (`settled()`) before the next one.
- Real gestures in the built app: open a project folder through the core socket from CDP (`window.simpleEffect.getCoreConnection()` gives the HTTP base: connect to `ws…/rpc?t=<token>`, send `openProject`, then set `location.hash` to `#/project/<id>`); a project without media can be made from the domain's example project (`crates/se-domain/src/document/snapshots/*example_project_json_format.snap`, body after the second `---`, as `project.json`). Media bin drags need `Input.setInterceptDrags` then `Input.dispatchDragEvent` with the intercepted data; keep the drop point inside the window.
- `TimelinePanel.test.tsx` renders the timeline over a session (`features/timeline/testing/fixtures.ts`: `seconds`, `testItem`, `testTrack`, `testSequence`, `testAsset`) inside a `ShortcutProvider`; it drives selection with `fireEvent.pointerDown` (pointer capture is stubbed in `vitest.setup.ts`), the marquee by mocking the lanes' `getBoundingClientRect`, and shortcuts with `userEvent.keyboard` (the timeline claims the shortcut context on mount). In jsdom the lanes measure 0 px, so the zoom stays at 50 px/s and only items of the first seconds render.
- Performance in the built app: `pnpm generate-test-project`, open the folder, then measure frame times over CDP while sending `Input.dispatchMouseEvent` wheel events at the lanes (`[data-timeline-lanes]`); keep the real mouse out of the window, it cancels synthetic drags.
- Graphics tests share `shared/project-store/testing/graphics-fixture.ts` (`graphicsSession()`: texts `title` (opacity keyframed) and `plain`, `textKind`, `documentColor('ffffff')` — the raw-colour guard rejects colour literals even in tests). `GraphicsInspector.test.tsx` (sections, one command per step, drag previews, auto-keyframing, keyframe toggles, patches of every selected text), `TransformGizmo.test.tsx` (drives the gizmo over a fake engine's `emitLayout`; the viewer's zoom is saved in `se.ui.viewer.v1` before rendering because jsdom measures 0 px), `KeyframeLane.test.tsx`, `GraphicsTools.test.tsx` (`T`, shapes menu, presets panel).
- Prompt 16 tests: `features/sequences` (`sequence-services.test.ts`: bounds, text extents, format values, items leaving the frame; `SequenceDialogs.test.tsx`: format dialog with the frame rate locked, policies, the out-of-frame toast and « Sélectionner » — the send mock loads the patched session before answering —, versions, removal), `SequenceTabs.test.tsx`, `ReframeInspector.test.tsx` + `services/reframe-switch.test.ts`, `ViewerReframe.test.tsx` (guides per sequence, reframing drag, double click, leaving the mode) + `services/viewer-guides.test.ts`. Sonner renders a toast twice (list and live region): use `findAllByText(...)[0]`.
- `ViewerPanel.test.tsx` renders the viewer over a session with `createEngine` = `fakeEngineFactory()` (`features/viewer/testing/fake-preview-engine.ts`, records scene, time, proxy, background, size, playback; `emit(state)` simulates loading and issues) and `createAudio` = `fakeAudioFactory()` (`testing/fake-audio-engine.ts`: a clock the test moves with `now`, recorded transport and scrubs, fixed levels). Playback ticks run on jsdom's `requestAnimationFrame` (`nextFrame()` helper); click the picture first so the `viewer` shortcuts are live; use clock times inside frames (a time exactly on a frame boundary may land on either side in floating point). `services/playback-session.test.ts` drives a session in Node with a manual ticker. Without an injected factory (app shell tests), jsdom has no WebCodecs and the viewer shows « Aperçu indisponible »: no PixiJS is loaded. The real engine is tested in `packages/engine` (golden frames).
- Real engine in the built app: the dev build exposes `window.simpleEffectPreviewStats()` (decoder pool counters: open `VideoFrame`s, cached pictures) for leak checks over CDP.
- Playback in the built app (prompt 13, macOS): make media with the pinned ffmpeg (`resources/bin/<platform>/ffmpeg`, e.g. `testsrc2` with `drawbox` flashes and an `aevalsrc` beep each second), create the project and import through the core socket from CDP (`createProject`, `importMedia`, then `placeMedia` with `{ kind: 'new' }` tracks once `getProjectSnapshot` shows decodability), set `location.hash`, turn the HUD on, dispatch `pointerdown` on `[data-viewer-picture]` (viewer context) and `keydown` events (`' '`, `l`, `k`, `{ key: 'l', metaKey: true }` on macOS) on `window`, and read the HUD text, `[role=meter]` values and the playhead timer. A CPU profile over CDP (`Profiler.start/stop`) tells a busy main thread from a stalled decoder.
- `MediaBinPanel.test.tsx` renders the panel with the providers it needs, a never-connecting `CoreClient` (spy `send` to answer) and a fake bridge; it drops files with `fireEvent.drop` and a `dataTransfer` of `File`s.
- Real drag and drop in the built app: CDP `Input.dispatchDragEvent` with `data.files` (absolute paths) gives the page `File`s whose path `webUtils.getPathForFile` knows (used for prompt 08's check).
- Manual: `pnpm dev` from the root (builds se-core, downloads the Electron binary on first run, opens the window).
- Built app with an isolated profile (as done for prompt 07 on macOS): `pnpm exec electron-vite build --outDir <tmp>/out`, add `<tmp>/out/package.json` with `{"type":"module","main":"main/index.js"}`, then `SE_CORE_PATH=<repo>/target/debug/se-core pnpm exec electron <tmp>/out --user-data-dir=<tmp>/profile --remote-debugging-port=9223` and drive it through `http://127.0.0.1:9223/json` (CDP). After rebuilding, reload with `Page.reload { ignoreCache: true }` (a plain reload keeps the old `index.html`).
- Packaging: `pnpm package` from the root → `apps/desktop/release/` (config in `electron-builder.yml`).
